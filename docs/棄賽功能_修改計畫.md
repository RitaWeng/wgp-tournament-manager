# 棄賽功能修改計畫書（code review 後續）

> 產生背景：對 `feat/team-withdrawal` 分支（基準 commit `4d86a2e`）做完整 code review 後的修復計畫。
> 本文件供接手的開發者／模型執行，**依優先級由上往下修**。
> 行號以 review 當下為準，修改過程會位移，請以「搜尋錨點」的程式碼片段定位。
> 相關設計文件：`docs/棄賽功能_評估與設計.md`。

## 背景：功能現況

- 資料模型：每位選手（隊伍）新增 `status: 'active' | 'withdrawn'` 與 `withdrawnRound: number | null`。
- App 端配對過濾：`generateSwissPairings` 只用 `p.status !== 'withdrawn'` 過濾（`TournamentManager.tsx` ~1013）。
- 回歸測試 `tests/regression/replay_excel.js` 則用 round-aware 的 `withdrawnRound > target` 過濾——**兩邊語意不一致**，這是多個問題的根源。
- 排名：`calculateScores` 內把棄賽隊 `rank = null`，只對 active 隊伍排名。

## P0 — 阻斷性：棄賽生效後該輪無法算分 ✅（已修，commit `dacb792`；後續 P1 已將檢查改為 round-aware 的 `isActiveForRound`）

**檔案**：`tournament-menager/src/TournamentManager.tsx` ~2029
**錨點**：`// 檢查2（hard）：有選手未排入本輪`

`getPairingIssues` 的檢查 2 遍歷**全部** `players`。棄賽隊不在本輪桌次 → 產生 hard error → `calculateScores`（錨點 `if (hardErrors.length > 0)`，~1095）直接 return。**任何在棄賽生效後抓對的輪次都無法算分**，功能主流程直接卡死。

**修法**：檢查 2 只遍歷在賽隊伍：

```js
players.filter(p => p.status !== 'withdrawn').forEach(p => { ... });
```

（若已完成 P1 的單一事實來源重構，改用共用的 `isWithdrawn(p)` / eligibility helper。）

**驗收**：標記一隊棄賽 → 抓對下一輪 → 按「算分」能正常計分，不出現「未排入本輪配對」hard error。同時確認：棄賽隊「該隊已打過的舊輪次」若重新驗證配對（🔍 驗證配對按鈕）不應誤報。

## P1 — 資料模型：以 `withdrawnRound` 為唯一事實來源 ✅（已修：`status` 欄位移除，`isWithdrawn`/`isActiveForRound` 共用 helper 進 `swissPairing.js`，App 與 replay 過濾統一為 round-aware）

**檔案**：`TournamentManager.tsx`（多處）

兩個互相耦合的問題一起修：

1. **雙欄位冗餘**：`status` 完全可由 `withdrawnRound != null` 導出，但 App 內 `withdrawnRound` 目前**只寫不讀**，所有行為判斷都走 `status`。兩欄位必須在 5 個寫入點保持同步，是 bug 溫床。
2. **過濾語意錯誤**：App 過濾是全域布林（`status !== 'withdrawn'`），但確認視窗承諾「從第 N 輪起不再被抓對」（`withdrawnRound = effectiveRound`）。若標棄賽後回頭重抓較早輪次（App 支援回到先前輪次重配，會清掉後續輪次），該隊會被提前踢出它其實有打的輪次。回歸測試 `replay_excel.js` 的過濾是對的（`withdrawnRound > target`），App 反而是錯的。

**修法**：

- 保留 `withdrawnRound: number | null` 為唯一狀態；`status` 欄位整個移除（或保留為衍生值但不做判斷依據）。
- 新增共用 helper（建議放 `tournament-menager/src/lib/swissPairing.js`，replay 也能 import）：

```js
// round 該輪是否在賽（withdrawnRound 為 1-based 生效輪）
export function isActiveForRound(player, round) {
  return player.withdrawnRound == null || round < player.withdrawnRound;
}
```

- App 端 `generateSwissPairings` 過濾改為 `isActiveForRound(p, currentRound)`。
- `replay_excel.js` 改為 import 同一個 helper（刪掉手刻的鏡像過濾，消除語意漂移）。
- 所有 `p.status === 'withdrawn'` 判斷改為 `p.withdrawnRound != null`（UI 顯示用，表示「已宣告棄賽」）或 `!isActiveForRound(p, round)`（輪次相關邏輯），依語意選擇。
- 兩個載入路徑的向後相容補欄位、兩處預設選手物件字面值（見 P4）一併只補 `withdrawnRound`。

**注意**：`handleToggleWithdraw` 的 `effectiveRound` 計算邏輯不變（當輪已排桌 → 下輪生效；未排桌 → 當輪生效），但現在它真的會被讀取、產生行為。

**驗收**：第 3 輪已排桌時標棄賽（視窗顯示第 4 輪起生效）→ 回到第 3 輪重新抓對 → 該隊**仍在**第 3 輪配對池中；切到第 4 輪抓對 → 該隊被排除。

## P2 — 名次：棄賽／恢復參賽後立即重排 ✅（已修：抽出 `recomputeRanks`，toggle 後立即重排；賽前無成績時不重排以保留初始籤號名次；順帶修掉 P4-3 的 stale closure——toggle 改用 functional setState）

**檔案**：`TournamentManager.tsx`
**錨點**：`handleToggleWithdraw`（~732）、`calculateScores` 內 `// 更新排名`（~1166）

`rank` 只在 `calculateScores` 更新。後果：

- 最後一輪算分**之後**才標棄賽：該隊保留舊名次（匯出 Excel 照寫），其他隊名次斷號（1,3,4…），且不會再有算分來修正。
- 「恢復參賽」後 `rank = null`，若之後沒有再算分，該隊永遠沉底顯示「—」，正式成績無法修復。

**修法**：把 `calculateScores` 中「輔分計算 + 排名分配」段落（從 `calculateAuxiliaryScores` 呼叫到並列名次分配結束）抽成獨立函式，例如：

```js
const recomputeRanks = (playerList) => { /* 輔分 + rank 分配，回傳新陣列 */ };
```

`calculateScores` 與 `handleToggleWithdraw`（棄賽與恢復兩個分支）都呼叫它。toggle 時以現有成績重算即可（不需要重算 rounds/totalScore）。

**驗收**：最後一輪算分後標記第 2 名棄賽 → 名次表立即顯示連號（原第 3 名變第 2）；再按恢復參賽 → 該隊回到原名次。全程不需再按算分。

## P3 — 渲染：投影視圖與緊湊視圖的棄賽處理 ✅（已修：投影視圖棄賽隊沉底＋凍結分數排序＋棄賽標記／無獎盃；緊湊視圖突顯卡只取在賽隊。順帶提前完成 P5-1：`compareByScoreThenAux` 已抽入 `swissPairing.js` 供 `getSortedPlayers` 與投影視圖共用）

### P3a 投影名次表（觀眾投影，影響最大）

**錨點**：`renderStandingsProjection`（~2679）

完全沒有棄賽處理：只按 `rank || 9999` 排序，無棄賽 Pill／刪除線／變暗。配合 P2 的 stale rank，領先隊被標棄賽後投影畫面仍顯示它掛皇冠的「冠軍」卡。多支棄賽隊之間順序未定義，與名次表頁的凍結分數排序矛盾。

**修法**：改用 `getSortedPlayers()`（它已處理棄賽沉底與凍結分數排序），並在卡片上加與表格視圖一致的棄賽標記（`棄賽` Pill + `line-through` + `opacity-55`），`isTop3`／獎盃判斷需排除棄賽隊。

### P3b 緊湊視圖「領先三隊」卡片

**錨點**：`renderCompactStandings` 內 `hasRanking` / `top3` slice（~2228）

`top3 = slice(0, 3)` 不檢查狀態；小型賽事（4 隊退 2 隊）棄賽隊會補進突顯卡片，而 top-3 卡片分支沒有任何棄賽樣式。

**修法**：top3 只從在賽隊伍取（先 filter 掉棄賽隊再 `slice(0, 3)`），棄賽隊一律進「其他」列表（該處已有完整棄賽樣式）。

**驗收**：4 隊賽事標 2 隊棄賽 → 緊湊視圖突顯卡只有 2 張（皆為在賽隊）；投影視圖棄賽隊沉底、有棄賽標記、無獎盃。

## P4 — 一致性與防呆 ✅（已修：1. 匯出輪空寫 0、棄賽隊名次欄標「棄賽」；2. 核心增 `allPlayers` 選項，App 與 replay 都傳完整名單算 float balance；3. 已於 P2 一併修）

1. **Excel 匯出輪空寫成空白**（`exportToExcel`，錨點 `round.opponent ? round.opponent : ''`，~1265）：輪空（opponent=0）應明確寫 `0`，否則 App 匯出的檔案當 fixture 時，最後一輪輪空的隊會被 replay 解析器誤判為棄賽（新規則：空白＝棄賽、0＝輪空）。同時在選手成績表加一欄「棄賽」（或名次欄寫「棄賽」字樣），讓官方成績表可讀。
2. **float balance 把退賽對手當 0 分**（`tournament-menager/src/lib/swissPairing.js`，錨點 `computeFloatBalance` 內 `scoresBefore.get(rd.opponent) ?? 0`，~70）：核心收到過濾後名單，退賽對手不在 map 中 → 分數視為 0，可能反轉升降級記錄。修法：`generateSwissPairingsCore` 增加可選參數 `allPlayers`（預設 = 傳入名單），`computeFloatBalance` 用 `allPlayers` 建 `scoresBefore`；App 與 replay 呼叫端都傳完整名單。**replay 引擎有同樣問題，兩邊要一起修，否則回歸測試互相印證不出來。**
3. **stale closure**（`handleToggleWithdraw` 兩處 `setPlayers(players.map(...))`，~744 / ~761）：`await dialog.confirm` 期間若有其他 state 更新落地會被覆蓋。改 functional form：`setPlayers(prev => prev.map(...))`。

## 驗證方式

1. **回歸測試**：`node tests/regression/replay_excel.js` — 四個 fixture（含 2026 北區／南區 GM5 棄賽樣本）全部 ✓。P1 改動後 replay 應 import 共用 helper，測試意義才成立。
2. **手動流程**（`tournament-menager/` 內 `npm run dev`）：
   - 建 6 隊 → 抓對 R1 → 算分 → 標 1 隊棄賽 → 抓對 R2（5 隊，應有輪空）→ **算分成功**（P0）。
   - 名次表／緊湊視圖／投影視圖三處檢查棄賽標記與名次連號（P2、P3）。
   - 回頭重抓已打輪次，確認棄賽隊仍在該輪（P1）。
   - 匯出 Excel：輪空寫 0、棄賽隊有標示（P4-1）。
   - 舊存檔（無 status/withdrawnRound 欄位的 JSON）匯入不炸、預設為在賽。
3. **建置**：`npm run build` 通過。

## 風險備註

- P1 移除 `status` 欄位會觸及存檔格式：載入端已有補欄位機制，但**匯出的 JSON 不再含 `status`**，若有外部工具依賴此欄位需確認（目前 repo 內無其他讀取者）。
- P2 抽出 `recomputeRanks` 時注意 `calculateAuxiliaryScores` **會 mutate 輸入物件**（見 `swissPairing.js` 註解），呼叫前要先深拷貝或確保傳入的是新陣列。
- 行號會隨修改位移，動手前先用錨點字串 grep 定位。
