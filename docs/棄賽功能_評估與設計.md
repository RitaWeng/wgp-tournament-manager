> 對象專案：`RitaWeng/wgp-tournament-manager`（WGP GiveMe5 瑞士制賽會管理工具）
> 文件日期：2026-06-05
> 結論先講：**目前沒有棄賽功能**，但架構很適合擴充，改動面小。

> **更新（2026-06-13）：本功能已實作完成。** 範圍依本文設計，棄賽輪次採「**從下一個尚未配對的輪次起生效**」

> 亦同步支援棄賽偵測，並新增 `tests/fixtures/2026南區.xlsx`（含 4 隊 R1 後棄賽）作為回歸樣本。

## 一、結論

整個專案只有「**輪空（BYE）**」的概念，完全沒有「棄賽 / 棄權 / withdraw / forfeit」相關邏輯。

若現在有隊伍中途退賽，系統會**繼續把它排進後續每一輪的對戰**，只能靠手動改桌次來閃避，沒有正規處理方式。

---

## 二、現況分析（為什麼目前無解）

| 面向 | 現況 | 位置 |
| --- | --- | --- |
| 選手資料模型 | 沒有任何「狀態 / 是否參賽中」欄位 | `TournamentManager.tsx:833` |
| 配對演算法 | 把 `players` **全員**排進去，只認得「輪空（player2=0）」，不認得「這隊不該再被配對」 | `swissPairing.js:199` `generateSwissPairings` |
| 人數鎖定 | 一旦任一輪已生成桌次，「參賽隊伍 / 輪數」即鎖死，無法靠改人數移除 | `TournamentManager.tsx:2678`（註解） |

目前選手資料結構（`TournamentManager.tsx:833`）：

```js
{
  number, name, level, country,
  totalScore, rank,
  auxScore1, auxScore2, auxScore3,
  rounds: [{ score, opponent, isBlack }]
}
```

**好消息：架構很適合擴充。** 配對是一個純函式模組（`swissPairing.js`），React 端只是薄包裝層（`generateSwissPairings` wrapper，`TournamentManager.tsx:973`）。
這代表新增棄賽功能可以**完全不動演算法核心**，也不必動現有回歸測試。

## 三、採用的規則決策（已拍板，2026-06-05）

| # | 決策項目 | 結論 | 理由 |
| --- | --- | --- | --- |
| 1 | 退賽隊在排名表怎麼呈現 | **一律排到最後、不佔正式名次**，標「棄賽」 | 符合多數正式賽會「退賽不列正式排名」慣例，現役隊名次乾淨連號 |
| 2 | 退賽隊已打成績對「其他隊」輔分是否照算 | **照算** | 瑞士制慣例：退賽前的對戰是有效戰績，仍計入對手的輔分一/二，不需特判 |

細節說明：

1. **排名表呈現（決策 1）**：退賽隊一律沉到表格最後一區、不分配正式名次（rank），並加上「棄賽」標籤；現役隊照原本的（總分 → 輔分）排序佔正式名次。
2. **輔分計算（決策 2）**：退賽隊已打過的成績照算，仍正常計入其**過往對手**的輔分一/二 —— 這是瑞士制的標準處理。注意此處只影響「別人的」輔分，退賽隊自己不列正式名次（與決策 1 一致）。

## 四、建議的新增設計（最小侵入，依現有架構）

### 1. 資料模型：加狀態，不要刪資料

棄賽是「標記」，不是「刪除」（必須保留已打完的成績與對手歷史）。在 player 上新增兩個欄位：

```js
status: 'active' | 'withdrawn'   // 預設 active；舊存檔讀進來一律視為 active
withdrawnRound: number | null    // 從第幾輪起退出
```

- 讀檔 / 匯入時對缺欄位做向後相容：`p.status ?? 'active'`。
- 存檔（`appState`，`TournamentManager.tsx:557` / `:654`）一併帶上這兩個欄位。

### 2. 配對：只在 wrapper 過濾，核心不動

在 React 端 `generateSwissPairings`（`TournamentManager.tsx:979`）呼叫核心**前**，先過濾出 active 名單：

```js
const activePlayers = players.filter(p => p.status !== 'withdrawn');
const result = generateSwissPairingsCore(activePlayers, currentRound, { allowSameCountry });
```

效果：

- 退賽隊不會再被排進新桌次。
- 對手歷史記在各人自己的 `rounds[].opponent` 裡，不受影響（過往對戰仍被正確避開重複）。
- 人數奇偶變化（→ 是否需要輪空）由核心自動處理。
- **`swissPairing.js` 與回歸測試完全不用改。**

### 3.「當輪已配對才退賽」→ 對手記不戰而勝（walkover）

若某隊在桌次已生成後才退賽，其當輪對手要拿到 walkover 勝分。建議：

- 在該 match 上記 `forfeit: true`。
- 在 `calculateScores`（`TournamentManager.tsx:1075`）比照輪空分支處理：自動給對手 `winPoint`、退賽方 0 分。
- 顯示「不戰勝 / 棄賽」標籤，沿用現有 `Pill` 元件（類似 `TournamentManager.tsx:2065` 的「輪空勝」呈現）。

### 4. 成績與輔分：凍結即可，不必特判

- 退賽隊保留已得分數，之後不再得分。
- 現有輔分一/二（`swissPairing.js:107`、`:117`）是「對手 totalScore 之和」；退賽隊分數凍結後，仍正常被其過往對手計入 —— 正是瑞士制標準處理，**輔分邏輯零改動**。

### 5. UI

- 在選手列 / 排名表每列加一個「**棄賽**」按鈕，跳現有 `dialog.confirm` 確認，並詢問「從第幾輪起」。
- 排名表排序時，先把 `status === 'withdrawn'` 的隊伍**全部沉到最後一區**，現役隊照原本的（總分 → 輔分）排序佔正式名次；退賽隊之間可再依凍結分數排序，但**不分配正式名次（rank）**，並用 `Pill` 標「棄賽」、加一條分隔（如「以下為棄賽隊伍」）。
- 提供「**恢復參賽**」的反向操作（改回 `active` 後重新納入正式名次與配對池）。

## 六、邊界情況備忘

- **奇偶變化**：退賽造成剩餘人數變奇/偶 → 輪空安排由核心自動處理，無需手動介入。
- **退賽後又恢復**：`status` 改回 `active` 即可重新進入配對池；其凍結期間的 `rounds` 應維持原狀。
- **全部對手都打過 / 都輪空過**：核心已有對應的無解提示（`swissPairing.js:351`），退賽縮小人數後此情境更可能出現，UI 的「抓對失敗」對話框會照常顯示。
- **匯入舊存檔**：務必補 `status ?? 'active'`，否則舊資料的 player 會是 `undefined` 狀態而被誤判。
